## 📋 План правок v0.2

### 1. Rezka.ag парсинг — не находит стрим со страницы
**Проблема:** Вставляешь ссылку на страницу фильма (`https://rezka.ag/film/...html`), но парсер не находит m3u8. Работает только прямая m3u8 ссылка.
**Причина:** Текущий `_download_rezka()` пытается парсить HTML и делать POST на `/ajax/video`, но rezka часто меняет структуру, требует translator_id, season/episode параметры для сериалов, CSRF-токены.
**Решение:**
- Использовать подход из RezkaVideo проекта (`parse_m3u8.py`) — там уже рабочий парсер
- Или: добавить поле "Источник" в UI — пользователь сам выбирает: "Прямая m3u8" / "YouTube" / "Страница rezka.ag"
- Для rezka: парсить страницу через requests с правильными headers, искать `video_id` + `translator_id`, POST запрос
- Поддержка сезонов/серий для сериалов
- Fallback: если парсинг не удался, показать инструкцию "Открой видео в браузере, найди m3u8 в Network tab"

### 2. Субтитры — нет возможности поставить после анализа
**Проблема:** После вставки ссылки и анализа, автоматически перекидывает на шаг "Fragments". Лирика не переносится, кнопка "Auto-split" не работает если лирика не передана.
**Решение:**
- НЕ автопереход на шаг 2 после анализа. Показать "Анализ OK" и остаться на шаге 1
- Добавить кнопку "Next" вручную
- На шаге Subtitles: textarea для лирики (если ещё не введена)
- SubtitleEditor берёт lyrics из общего state

### 3. Рендер прогресс — реалтайм мониторинг
**Проблема:** При рендере нет индикации прогресса — просто "Rendering...".
**Решение:**
- Backend: рендер в background task (asyncio.create_task)
- Backend: парсинг ffmpeg stderr для прогресса (regex на `frame=` или `time=`)
- Backend: endpoint `GET /api/render/{job_id}/status` → {status, progress: 0-100}
- Frontend: polling `/api/render/{job_id}/status` каждые 2 секунды
- Frontend: прогресс-бар + проценты + elapsed time
- Frontend: ffmpeg stderr лог (опционально для дебага)

### 4. UI/UX правки (мелкие)
- Шаг 1: после анализа не прыгать на шаг 2 автоматически
- Шаг 2 (Fragments): автогенерация фрагментов при входе (если пусто)
- Шаг 3 (Subtitles): автогенерация субтитров при входе (если лирика есть)
- Кнопка "Skip" для шага Style (стиль по умолчанию)
- Кнопка "Start over" для сброса всего

### 5. Выбор фрагмента аудио
**Проблема:** Рендер берёт аудио с начала. Если трек 3 минуты, а клип 30 секунд — используется первые 30 сек. Хочется выбрать конкретный кусок (например припев с 1:15 до 1:45).
**Решение:**
- UI: аудио-плеер с waveform (или timeline) + два ползунка "start" и "end"
- Backend: в `render_clip()` добавить параметры `audio_start` и `audio_end`
- ffmpeg: `-ss {audio_start} -t {audio_end-audio_start}` перед `-i audio.mp3`
- По умолчанию: начало трека (как сейчас)
- Опция: "Auto-select loudest part" — ffmpeg `volumedetect` для пика/припева
- Опция: "Loop audio if shorter than video" — зациклить трек если короче клипа

### 6. Размер текста субтитров
**Проблема:** Текущий размер слишком мелкий для TikTok.
**Решение:**
- Увеличить дефолт с 48px до 64-72px
- В StyleEditor расширить диапазон слайдера: 24-120px
- Пресеты: "Small (48)", "Medium (64)", "Large (80)", "Huge (96)"
- Превью в StyleEditor масштабировать

## 🎯 Синхронизация трека и текста — профессиональный разбор

### Уровень 0: Равномерное распределение (сейчас)
Каждое слово получает равную долю времени строки. Просто, но рассинхрон с музыкой.

### Уровень 1: Распределение по слогам
Считаем слоги в каждом слове, распределяем время пропорционально.
- Плюс: точнее равномерного, не нужен AI
- Минус: всё ещё не синхрон с реальным вокалом
- Реализация: Python syllable counter (гласные = слоги), ASS `\kf` генерация

### Уровень 2: WhisperX — Word-Level Timestamps 🔥
**Золотой стандарт для ASR-синхронизации.**
- WhisperX = OpenAI Whisper + wav2vec2 forced alignment
- Даёт точные timestamps для каждого слова из аудио
- Работает с музыкой где есть вокал (рэп = вокал!)
- Точность: ±20мс на слово
- Пайплайн: `audio.mp3 → WhisperX → word_timings.json → ASS \kf генерация`
- Скорость: ~10-30с для 3-минутного трека (на GPU быстрее)
- Плюс: идеальная синхронизация с реальным вокалом
- Минус: нужен WhisperX (pip install), ~2GB модель, CPU медленнее

### Уровень 3: Forced Alignment (Aeneas / MFA)
- **Aeneas**: Python forced alignment — выравнивает известный текст к аудио
- **Montreal Forced Aligner (MFA)**: академический стандарт, acoustic models
- Пайплайн: `audio.mp3 + lyrics.txt → aligner → word_timings.json`
- Плюс: не нужно распознавать речь (текст уже есть), очень точно
- Минус: Aeneas медленный (60+ сек), MFA сложная установка
- **Aeneas проще** для нашего case — текст известен, нужно только выровнять

### Уровень 4: Beat Detection + Lyric Mapping
- **librosa** для детекции битов/темпа аудио
- Разбить аудио на сегменты по energy envelope
- Натянуть строки лирики на бит-структуру
- Плюс: синхрон с битом, выглядит "гарантированно" с музыкой
- Минус: слова внутри строки всё равно равномерно

### Уровень 5: Ручная подстройка (Tapping)
- UI: аудио-плеер, пользователь слушает трек и нажимает Space на каждом слове
- Записываются timestamps → генерация ASS
- Плюс: 100% точность, пользователь контролирует
- Минус: ручная работа, ~3 минуты на 30-сек клип

### Уровень 6: LRC Import
- Если у трека уже есть .lrc файл (распространённый формат караоке)
- Парсинг LRC → word timings → ASS генерация
- Плюс: мгновенно, если файл есть
- Минус: не у всех треков есть LRC

## 🎨 Визуальные подходы — как сделать профессионально

### A. Классический караоке-fill (ASS `\kf`)
Слово плавно закрашивается цветом слева-направо. Непропетое = серый, пропетое = белый/неон.
Реализация: ASS `\kf{мс}слово` в ffmpeg. Работает из коробки.

### B. Word Pop-in (современный TikTok-стиль)
Каждое слово появляется с scale 0→1.1→1.0 за 80мс. Активное слово крупнее, соседние бледнее.
Реализация: HTML/CSS оверлей вместо ASS. Рендер через Playwright (браузер) или After Effects.

### C. Progressive Box Highlight
Полупрозрачный бокс скользит под словами синхронно. Как в CapCut — активное слово в подсвеченном блоке.
Реализация: ASS `\fad` + positioned background. Или HTML оверлей.

### D. Neon Glow Pulse
Активное слово пульсирует неоновым свечением. RGB glow эффект, sync с битом.
Реализация: ASS `\fad` + `\bord` + `\shad`. Или HTML с CSS `text-shadow` animation.

### E. 3D Depth / Parallax
Активное слово "выпрыгивает" к зрителю (scale + blur neighbors). Остальные слова слегка размыты.
Реализация: HTML/CSS transform + blur. Только через браузер-рендер.

### F. Typewriter (Letter-by-letter)
Буквы появляются по одной, как печатная машинка. Каждая буква подсвечивается в момент произнесения.
Реализация: ASS `\kf` на символьном уровне. Нужен char-level timing.

### G. Beat-Reactive
Текст "пульсирует" с битом — масштаб меняется на каждом ударе. Активное слово получает bounce.
Реализация: librosa beat detection → timestamps → ASS scale keyframes.

## 🏆 Рекомендация: поэтапная реализация

### MVP+ (быстро, качественно):
1. **Syllable-based distribution** вместо равномерного
2. **ASS `\kf`** для плавной заливки
3. **Два цвета** — пропетое (белый/неон) vs непропетое (серый)
4. **Fade-in/out** на строках — появление/исчезновение
5. **Увеличенный шрифт** — 64-80px дефолт

### Pro (следующий шаг):
6. **WhisperX** для word-level timestamps — идеальный синхрон
7. **Beat detection** через librosa — pulse-эффект на бите
8. **LRC import** — если есть timed lyrics файл

### Pro+ (wow-фактор):
9. **HTML/CSS оверлей** вместо ASS — pop-in, glow, 3D depth
10. Рендер через Playwright (headless Chrome записывает анимированный текст)
11. **Ручная подстройка** tapping mode — для перфекционистов

## 💡 Креативные идеи (вдохновение)

| Идея | Описание | Эффект |
|------|-----------|--------|
| **TikTok-style** | Текущее слово в цветном блоке, остальные мелкие | Как CapCut авто-субтитры |
| **Rap-карaoke** | Слог под слог, bounce на акцентах | Как в караоке-барах |
| **Glitch-стиль** | Слова мерцают, glitch на переходах | Aesthetic для рэпа |
| **Subtitle box** | Чёрный полупрозрачный бокс, слово подсвечивается | Чисто, читаемо |
| **Two-line** | Текущая строка сверху, следующая серая снизу | Классика караоке |
| **Confetti** | Частицы на переходе строки/припеве | Wow-фактор |
| **Audio waveform** | Waveform внизу, синхрон с текстом | Профи-вид |
